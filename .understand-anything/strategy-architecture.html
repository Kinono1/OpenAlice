Regime Classifier (单资产)

  • event-risk-freeze — 宏观事件冻结（最高优先）
  • vol-stress — 波动率 Pct ≥ 0.9 或成交量冲击 ≥ 2.5x
  • trend-follow — 趋势强度 ≥ 0.65 且波动率 ≤ 0.75
  • range-rotation — 范围压缩 ≥ 0.6 且波动率 ≤ 0.45
  • spot-defensive — 默认兜底
  • 可选 HMM 覆盖（method=hmm 且 confidence ≥ floor）: bull→trend, bear→bear, calm→range, stress→vol

Signal Governance (L/U/D/S)

  • SourceTier — L1-L5（数据源质量）
  • UseType — U1-U4（用途分类）
  • DecisionStrength — D1-D5（|value|×confidence 推算）
  • SentimentCrowding — S+2 到 S-2
  • ActionStatus: attack / attack-lite / probe / hold / reduce / exit / no-trade
  • 事件冻结时 cap 为 reduce/exit/no-trade/hold

UTA / Bridge 注入

  • Stage — stagePlaceOrder() / stageClosePosition() / stageModifyOrder()
  • Commit — commit(message) → 8字符 hash
  • Push — 先读取 release gate 状态，再执行 staged operations
  • Reject — reject(reason) → 撤销暂存
  • CCXT Account — AccountManager 注入 ccxtExecutionBridge.wrapExecuteOperation

Strategy Preflight (条件调用)

  • reduceOnly — 仅在 adapter strategy preflight 内直接放行；更早的 UTA.push release gate 仍可能阻断
  • Release Gate — 读取 8 道验证结果状态；阻断时拒绝 place order
  • Runtime Integration — runtimeIntegrationEnabled 默认 false；未开启时拒绝新下单路径
  • Enabled Path — 生成上方 snapshot 与 executionPreview，决定阻断或调整有效数量
  • Approved — 由 dispatcher 继续交给 broker 执行

连接件当前实现状态 — 2026-06-02 源码复核
这些模块开始补跨调用/跨资产/跨路径缝合处，但不是全部完成态

① 持久化 IC 状态 partial

  • runtime-service.ts 已有 lazy load + debounced atomic save
  • 运行时写入 ic_monitor_snapshot.by_key.json，key 为 source|exchange|symbol|interval
  • ic_monitor_snapshot.latest.json 仍由 publish_ic_monitor_snapshot.ts 生成
  • 缺口 runtime-service 当前不生成 aggregate latest，因此 status:ic-monitor 不会自动读取新 by-key 状态

② Governance-Aware UTA Guard partial

  • Operation 新增 governance 元数据字段
  • GovernanceActionStatusGuard 从 operation.governance.actionStatus 读取状态
  • no-trade/exit/reduce → 阻止新开仓
  • closePosition / 风险降低订单 → 永远允许
  • 边界 只有在 guard 被配置且 staged operation 携带 governance metadata 时生效
  • 缺口 src/tool/trading.ts 的 placeOrder schema 当前未暴露 governance 输入

③ Portfolio Risk Overlay wired but defective

  • 纯函数 applyPortfolioRiskOverlay()
  • 按 broker 持仓 + pending ops 设计为计算组合级 cap
  • 在 runtime-service.ts 层调用（不污染 factor evaluator）
  • 配置 strategy.positionSizing.portfolioRiskOverlay
  • 缺口 runtime hook 目前有 'positions' in input 条件，公开输入类型不含 positions，实际大概率不会进入
  • 缺口 maxNetExposurePctOfEquity 配置存在，但 overlay 函数当前只实现 single-asset 与 gross cap
  • 缺口 pending ops 由 getPendingOrderIds() 映射为 notional=0，不能真实计入组合敞口
  • 缺口 overlay 修改 recommendedPct，但当前没有同步刷新 recommendedNotionalUsd

④ Paper→Runtime Config Proposal proposal-only

  • ConfigProposal 类型 + FACTOR_SIGNAL_TO_CONFIG 映射表
  • 当前仅实现 IC 衰减且 IC Sharpe 为负 → 建议降权
  • applyConfigProposal() 为 v1 stub
  • 第二版再加 read → clone → apply → parse → write 闭环
  • 边界 不读取真实 paper ledger；调用方需传入 factorMetrics
  • 缺口 映射表包含 carry/liquidation-after/orderbook/stablecoin 等 key，但当前 strategy config schema 未全部包含这些路径
结论：四个连接件不应画成全部完成。IC 持久化与 governance guard 是部分可用； paper config feedback 是 proposal-only；portfolio overlay 目前存在接线和计算缺口，不能视为有效组合风控。
